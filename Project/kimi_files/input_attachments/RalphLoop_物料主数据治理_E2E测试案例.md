# 基于 Ralph Loop 的物料主数据治理 E2E 测试案例

> 版本：v0.1  
> 日期：2026-05-06  
> 依据：[RalphLoop_物料主数据治理_PRD.md](RalphLoop_物料主数据治理_PRD.md)、[RalphLoop_物料主数据治理_最小US拆分.md](RalphLoop_物料主数据治理_最小US拆分.md)、[OpenMetadata_物料主数据自研服务集成设计.md](OpenMetadata_物料主数据自研服务集成设计.md)  
> 测试目标：验证“申请 -> 校验 -> 重复预检 -> 编码 -> 审批 -> Golden Record -> SAP BTP 受控发布 -> OpenMetadata 同步 -> Agent 安全 -> 审计追踪”的端到端闭环。

---

## 1. E2E 测试原则

### 1.1 Ralph Loop 测试策略

1. **先测线性主链路**：优先验证一条新增物料从草稿到 OpenMetadata 可见的完整路径。
2. **每轮只加一个变量**：R0 到 R7 按交付轮次逐步扩展，不在早期混入所有异常。
3. **真实验证优先**：优先使用真实数据库、真实 OpenMetadata API、BTP Mock/测试租户、SAP Mock/测试环境。
4. **上下文外置**：所有用例必须记录 `requestId`、`materialCode`、`traceId`、`btpTraceId`、`syncJobId`、`agentTraceId`。
5. **失败路径必须可见**：BTP 发布失败、OpenMetadata 同步失败、Agent 越权、编码冲突都必须有状态、错误、审计和重试/补偿路径。
6. **安全断言不可省略**：任何涉及 SAP 的 E2E 用例都必须断言：OpenMetadata 不直连 SAP、第三方 AI Agent 不直连 SAP、自研服务不绕过 BTP 直连 SAP。

### 1.2 全局通过标准

| 编号 | 标准 |
|---|---|
| G-001 | P0 主链路用例全部通过 |
| G-002 | SAP 直连违规数为 0 |
| G-003 | 所有 SAP 相关发布都有 `btpTraceId` |
| G-004 | 所有申请链路都有 `requestId` 和 `traceId` |
| G-005 | OpenMetadata 同步失败不阻塞 BTP 发布成功状态 |
| G-006 | Agent 不自动提交、不自动审批、不自动发布 |
| G-007 | 审计视图可按 `requestId` 串联申请、校验、查重、编码、审批、Golden Record、BTP、OpenMetadata、Agent 调用 |

## 3. 测试数据

### 3.1 基础分类与模板

| 字段 | 值 |
|---|---|
| 物料大类 | `RAW` / 原材料 |
| 物料小类 | `CHEM` / 化工原料 |
| 编码规则 | `RAW-CHEM-{属性段}-{流水号}` |
| 流水号初始值 | `000001` |
| 必填字段 | 物料名称、分类、基本单位、规格型号、供应商料号、用途说明 |
| 枚举字段 | 基本单位：`KG`、`EA`、`L`；危险品等级：`N/A`、`Class 3`、`Class 8` |

### 3.2 正常新增物料样例

| 字段 | 值 |
|---|---|
| 物料名称 | 乙醇 95% 工业级 |
| 物料分类 | 原材料 / 化工原料 |
| 基本单位 | `KG` |
| 规格型号 | `95%, 160KG/桶` |
| 供应商料号 | `SUP-ETHANOL-95-160` |
| 危险品等级 | `Class 3` |
| 用途说明 | 清洗工序使用 |
| 预期编码 | `RAW-CHEM-A1-000001` 或按实际规则生成 |

### 3.3 异常与边界数据
| 数据集 | 用途 | 示例 |
|---|---|---|
| 缺必填 | 提交强校验失败 | 缺少基本单位、规格型号 |
| 非法枚举 | 枚举校验失败 | 基本单位为 `BOX` |
| 格式错误 | 格式校验失败 | 规格型号为 `???` |
| 精确重复 | 重复预检高风险 | 相同供应商料号 `SUP-ETHANOL-95-160` |
| 模糊重复 | 重复预检中风险 | 物料名称 `工业乙醇95`，规格 `95% 160kg barrel` |
| 编码冲突 | 并发预留 | 两个申请同时抢占 `000001` |
| BTP 失败 | 发布失败重试 | BTP Mock 返回 `SAP_FIELD_MAPPING_ERROR` |
| OpenMetadata 失败 | 同步失败重试 | OpenMetadata Mock 返回 500 |
| Agent 越权 | 安全拦截 | Agent 请求 SAP 原始接口 URL 或批量导出 SAP 字段 |

## 5. TS-00 环境与基础数据

### TC-E2E-000 环境健康检查

**优先级**：P0  
**覆盖 US**：全局  
**目的**：确认 E2E 所需组件可用。

**前置条件**：测试环境已部署。

**步骤**：
1. 使用测试账号登录主数据门户。
2. 调用主数据服务健康检查 API。
3. 调用 BTP Mock/API Proxy 健康检查。
4. 调用 OpenMetadata API 健康检查。
5. 调用 Agent 能力网关健康检查。
6. 查询审计服务健康状态。

**预期结果**：
- 所有组件返回健康状态。
- 任何组件异常时，测试停止并记录阻塞项。

**证据**：健康检查响应、时间戳、环境版本。

### TC-E2E-001 角色权限基线检查

**优先级**：P0  
**覆盖 US**：US-003、US-012、US-025、US-040、US-058

**步骤**：
1. 分别使用申请人、Steward、Owner、主数据管理员、BTP 管理员、数据治理管理员、安全管理员、审计人员登录。
2. 验证每个角色只能访问对应菜单和 API。
3. 申请人尝试访问 BTP 发布错误详情。
4. 审计人员尝试修改申请单。

**预期结果**：
- 菜单和 API 权限符合角色定义。
- 申请人不可查看敏感 BTP 错误详情。
- 审计人员只读，不可修改。
- 拒绝访问动作进入审计。

**证据**：权限截图/API 响应、审计记录。

### TC-E2E-002 基础分类模板初始化

**优先级**：P0

**步骤**：

## 6. TS-01 主链路

### TC-E2E-010 新增物料完整闭环成功

**优先级**：P0  
**覆盖 US**：US-001 到 US-006、US-010 到 US-013、US-015、US-018、US-019、US-023 到 US-025、US-028、US-029、US-031 到 US-037、US-043、US-047、US-050、US-058

**目的**：验证 MVP 主链路可完整跑通。

**前置条件**：TC-E2E-000 到 004 已通过。

**测试数据**：正常新增物料样例。

**步骤**：
1. 申请人选择 `RAW/CHEM` 分类。
2. 系统加载字段模板。
3. 申请人填写正常新增物料样例并保存草稿。
4. 记录 `requestId` 和 `traceId`。
5. 申请人提交申请。
6. 系统执行强校验、重复预检、编码模拟和编码预留。
7. Steward 查看待办并初审通过。
8. Owner 查看待办并终审通过。
9. 系统确认编码并创建 Golden Record V1。
10. 系统生成 `MaterialCreated` Outbox 事件。
11. 发布服务调用 BTP API Proxy。
12. BTP Mock 返回成功、`btpTraceId` 和 `sapMaterialNo`。
13. 系统回写发布成功状态。
14. 系统同步 OpenMetadata 资产、术语、质量和血缘摘要。
15. 记录 `syncJobId`。
16. 审计人员按 `requestId` 查看全链路。

**预期结果**：
- 申请最终状态为 `completed` 或 `effective_published`。
- 物料编码已确认，编码解释包含 `ruleVersion` 和输入属性。
- Golden Record V1 存在，字段来源可查。
- 发布记录包含 `btpTraceId` 和 `sapMaterialNo`。
- OpenMetadata 可见 Golden Record 表资产、物料术语、质量结果、BTP API 资产和血缘摘要。
- 审计链包含创建、保存、提交、校验、查重、编码、审批、Golden Record、BTP 发布、OpenMetadata 同步。
- 未出现 SAP 直连接口地址。

**证据**：申请详情、编码解释、Golden Record、BTP 回执、OpenMetadata 截图、审计链截图。

### TC-E2E-011 主链路状态时间线检查

**优先级**：P0  
**覆盖 US**：US-058

**步骤**：
1. 使用 TC-E2E-010 的 `requestId` 打开全链路追踪页面。
2. 展开申请、校验、重复预检、编码、审批、发布、同步节点。
3. 检查每个节点的时间、操作者、状态和 trace 信息。

**预期结果**：
- 时间线顺序正确。
- 所有节点共享同一 `traceId` 或可关联 trace。
- BTP 节点显示 `btpTraceId`。
- OpenMetadata 节点显示 `syncJobId`。

**证据**：全链路追踪截图。

### TC-E2E-012 主链路重复执行数据隔离

**优先级**：P1  
**覆盖 US**：US-001 到 US-058

**步骤**：
1. 使用不同供应商料号创建第二条正常申请。
2. 完整执行主链路。
3. 对比两条申请的 requestId、materialCode、btpTraceId、syncJobId。

**预期结果**：
- 两条申请互不污染。
- 编码流水递增或按规则唯一。
- 审计链路按 requestId 隔离。

**证据**：两条申请对比表。

### TC-E2E-013 主链路无 OpenMetadata 直连 SAP 验证

**优先级**：P0  
**覆盖 US**：US-042、US-047

**步骤**：
1. 执行 TC-E2E-010。
2. 查看 OpenMetadata 同步任务输入参数。
3. 查看 OpenMetadata 连接器或服务配置。
4. 搜索同步日志中的 SAP 后端地址、SAP 技术用户名、SAP OData/RFC 直连配置。

**预期结果**：
- OpenMetadata 只接收自研服务和 BTP 摘要数据。
- 不存在 OpenMetadata 到 SAP 的直连连接器配置。
- 不存在 SAP 凭证或 SAP 后端直连地址。

**证据**：同步任务参数、配置扫描报告。

### TC-E2E-014 主链路无 Agent 直连 SAP 验证

**优先级**：P0  
**覆盖 US**：US-051、US-056、US-057

**步骤**：
1. 使用 Agent 用户执行相似物料查询。
2. 查看 Agent 工具调用日志。
3. 搜索工具配置中的 SAP 后端地址和 SAP 凭证。
4. 尝试让 Agent 请求 SAP 原始接口 URL。

**预期结果**：
- Agent 只调用白名单业务工具。
- 工具日志不包含 SAP 凭证或直连接口。
- 请求 SAP 原始接口 URL 被拒绝并审计。

**证据**：Agent 调用审计、越权拦截记录。

## 16. 缺陷分级

| 等级 | 判定标准 | 示例 |
|---|---|---|
| Blocker | 主链路无法完成或违反 SAP 不直连硬约束 | 发布绕过 BTP 直连 SAP；无法创建 Golden Record |
| Critical | 数据错误、审计缺失、安全边界破坏 | 编码重复；btpTraceId 缺失；Agent 可自动提交 |
| High | 关键异常不可恢复或状态不一致 | BTP 失败不可见；OpenMetadata 失败阻塞发布 |
| Medium | 功能可用但体验或信息不足 | 错误提示不清楚；看板统计延迟 |
| Low | 文案、展示、非核心字段问题 | 字段说明不完整 |
